### 第二十轮 — 触发行程改成竖向柱状滑轨
- **用户诉求**：「滑轨条不直观，竖着展示行程的拖动条怎么能是横着的，也要竖起来」，
  并附前行者官网「设置触发键程」截图作为参考样式。
- **问题本质**：触发设置页 AP 卡里，左边竖着一根行程柱、右边横着一根 `input[type=range]`，
  同一个「行程」概念出现两种方向 —— 表意打架。
- **方案：不用 `input[type=range]`，自绘竖向柱状滑轨**。
  原因：① 官方样式是「柱体填充 + 刻度数字 + 数值气泡」，不是细轨道 + 圆点 thumb；
  ② 让 range 竖起来要靠 `writing-mode` / `direction` / `-webkit-appearance` 的版本相关写法，Electron 打包后表现不稳。
- **新增组件** `src/components/VerticalTravelSlider.jsx` + `src/index.css` 里的 `.vtravel*` 一整块：
  - 结构：刻度列（主刻度 0.5 带数字 / 次刻度 0.25 只画短线，重合时跳过）+ 36px 宽柱体 + 渐变填充 + 跟随气泡（带铅笔图标）；
  - 交互：Pointer Events + `setPointerCapture`，`clientY` 反推 `value = (1 − Δy/H) × max`，支持点击轨道直跳；
  - 手感：`touch-action: none`；**拖拽中禁用过渡**，否则气泡会「追」指针；
  - 无障碍：`role="slider"` + `tabIndex=0` + `aria-valuemin/max/now/valuetext`；
    `↑↓←→` 微调、`Shift` 加速到 0.1mm、`Home`/`End`/`PageUp`/`PageDown`。
  - 刻度/填充/气泡全用百分比绝对定位，柱高由 `height` prop 定 → 换任意轴体行程自适应。
- **范围边界（用户拍板）**：**只竖 AP 这一根**。RT「按下/抬起灵敏度」与狂暴模式「按下/抬起死区」
  继续用横向 `input[type=range]` —— 问过用户，选择「就保持现在这样」。
- **踩坑：探针假阴性**。第一版探针拿 `getBoundingClientRect()` 的坐标直接 `Input.dispatchMouseEvent`，
  而柱体在滚动容器里 `top=670`，派发出的坐标没打中 → 拖拽后 `aria-valuenow` 纹丝不动，
  **被误判成「组件交互坏了」**。正解：读几何前先 `scrollIntoView({ block: 'center' })`，
  并**并行**用页面内合成 `PointerEvent` 再走一遍（绕过命中测试，只验 React 接线），两条路径分开判。
  改造后：B1 CDP 真实鼠标 ✅、B2 合成事件 ✅ —— 确认组件本身没问题。
- **新增探针** `tools/dump-vslider.cjs`：A 段结构 9 项 + B 段双路径交互，登记进 SOP §5.2（八个 → 九个探针）。
- **验收**：
  - `dump-vslider`：柱体 36×168 · 主刻度 `0.00/0.50/…/3.00` 共 7 个 · 次刻度 6 个 · `role=slider` · `tabIndex=0` ·
    `aria-valuenow=2` / `aria-valuemax=3.45` / `aria-valuetext=2.00mm` · 气泡带铅笔图标且严格跟随填充
    （`bottom 57.971%` vs 填充 `0.573`）；拖到 75% 高度 → `aria-valuenow=2.59`，**与期望 `max × 0.75` 完全一致**。
  - `scan-layout` 1100×700 与 1380×880：**9 个视图全绿**（0 重叠 / 0 键帽挤压 / 0 越界）。
  - `dump-late-mount`：三宽度 `OVERFLOW = −5 / −8 / −110`，全 ≤ 0。
  - 解包核对：`app.asar` 内 `dist/assets/*.css` 与 `*.js` 均含 `vtravel-*`（端到端确认新组件已入包）。
